# 原始需求（存档）

以下为最初的游戏设计要求；当前运行方式以项目 README 为准。

开局随机生成地图。单元格为正方形，每个单元格有平原，丘陵，高原，山脉，海洋，河流，湖泊等地形，每种地形具有相应的buff。

某些单元格会生成特定的资源，如石油，铁矿，煤矿，铜矿，金矿，银矿，稀土等。

多人游戏，顺便帮我做一下登录的部分。

玩家开局可以选择一个单元格建造城池。城池有等级，它的势力范围是一个以它为中心的正方形。边长等于 2*等级+1。所有的建筑必须建在城池的势力范围内。如果城池升级时新的势力范围与别人重合，则先到先得。

建筑有以下几种：

- 林场：产出木材
- 采石场：产出石头
- 铁矿，金矿，银矿，铜矿，油井：产出对应的矿物
- 粮田：产出粮食
- 养殖场：养殖牲畜，产出肉类，需要消耗粮食
- 仓库：提供仓储，存放物品
- 居民区：供居民居住
- 学校：提高居民的教育等级
- 公园，医院，商场等：提高舒适度
- 生活必需品工厂：如纺织厂，食品加工厂等
- 发电厂：火力，风力，太阳能等，各设施需要电力才能运转
- 自来水厂：生产自来水，需要建设在河流或湖泊旁边

所有建筑可以升级，升级后各能力相应提高。城池也可以升级。

林场等生产设施需要工人，且等级越高需要的人数越多。每个城池需要一定数量的公务人员，且等级越高需要的人数越多。工作人员不足时产量会降低，城市无法升级。

舒适度高且居住空间充足时人口会自然增长。舒适度低时人后会降低。

建筑需要成本以及各种原材料，建筑可以拆除，建造需要建筑工人和一定的时间。新建城池类似。

维持居民生存需要粮食，生活必需品，水，电力等，不足时舒适度下降。

物资可以通过全球市场与其他玩家进行贸易。可以一次性购买一定数量的物品也可以购买未来一段时间内的产能。如果被购买方产能不足需要赔偿违约金。玩家之间、同一玩家不同城市之间的物资调配需要运输，需要消耗一定的时间、金钱和人力，具体与城池之间的距离及之间的地形有关。如果中途需要经过第三方的领地，第三方可以禁运或收取关税。

官方商城可以收购或出售物资，一定周期刷新，具体与玩家之间的贸易类似，但是不需要运输。

写服务端和客户端，服务端需要给root账号各种管理功能，客户端使用electron。各种贴图可以用一些简单的像素画。游戏中具体数值帮我生成，注意游戏平衡性。
