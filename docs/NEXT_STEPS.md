# 下一阶段更新建议

以下为基于 2.0.1 当前玩法和交互的设计建议，**尚未开发，也不代表已安排的版本承诺**。

## 优先：物流 2.0，让自动化更有效也更容易理解

现有自动补货可以每种资源分别发货，小批次也至少占用一人；库存波动容易形成多条一两单位的运输。建议先改进：

- 同来源/目的城、同方式、相近发车时间的物资合成一批，按整批总载货量计算人力与运费，逐资源保留数量和容量校验。
- 可设置最小发货量、最长等待时间和紧急资源，短缺时立即发车，普通补货合单等待，避免微量库存反复触发。
- 发车前预览铁路/航空是否可用、预计时间/费用/工人、缺哪端设施或供给；记录每次自动调拨的触发原因和跳过原因。
- 运输面板按路线分组，保留仅参与者可见的隐私规则。

验收重点：同样的补货需求减少发车数和工人占用；等待上限明确，紧急物资不被饿死；合单不会让关税、接收容量或燃油扣除重复/遗漏。

## 第二步：城市规划与批量建造

- 拖拽铺设铁路，放下前显示路径、总造价、合法/非法地块。
- 拖框选择地块；批量拆除、升级和施工队列。
- 规划预览可撤销/重做，提交后由服务器统一校验；区分“规划”和“已付费施工”，避免直接提供经济回滚漏洞。
- 增加小地图与交通/矿藏/势力范围图层切换，选中城市时突出它的领地。

验收重点：几十格铁路不再需要几十次点击；失败地块有明确解释，批量动作的付费与回滚规则一致。

## 第三步：经济报表与生产链反馈

- 城市每周期收入/支出、净产出、运输费用，按物资展示历史变化。
- 库存预计还能维持多少周期，缺口来自人口、生产、运输还是销售。
- 点击原料能追踪它的生产建筑、上游消耗与下游用途；升级前预览净收益和新增人力/电力需求。
- 保存城市自动化模板，允许在自己的城池间复制补货/出售和预留设置。

验收重点：玩家能从报表判断缺货根因，升级建筑前能看见收益与配套成本。

## 后续：引导、协作与世界目标

- 新手目标链：首城→稳定供给→精炼→铁路→首次交易，直接指向对应操作，不强制阻挡熟练玩家。
- 联盟公共建设项目与自愿资源捐助，配合管理权限和可审计账目。
- 可选世界目标/排行榜：生产效率、贸易规模、居民生活水平等，按服务器配置选择，兼顾新玩家追赶。

建议顺序：**物流 2.0 → 批量规划 → 经济报表 → 引导与联盟协作**。每阶段围绕一个可验证的体验目标交付，逐步把已有系统连成清晰的经营循环。
